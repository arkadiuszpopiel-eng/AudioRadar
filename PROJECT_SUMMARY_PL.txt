PROBLEM 3: UI Białe Po Przełączaniu Zakładek (cały program się wysypuje!)
--------------------------------------------------------------------------
Zgłoszenie: "po kilku zmianach zakładek cały program wysypuje się pod
            względem UI daje zdjęcie całe jest białe!"

Przyczyna główna:
- Globalny stylesheet nie miał specyficznych reguł dla QTabWidget,
  QStackedWidget, tabele
- Podczas przełączania zakładek Qt resetował tła widgetów do systemowych
  domyślnych
- Widgety bez jawnych stylów wracały do QPalette domyślnych = białe tła
- Dziedziczenie stylesheet łamało się podczas dynamicznego tworzenia widgetów

Rozwiązanie - Rozszerzenie Globalnego Stylesheet (main.py linie 291-333):

1. Dodano jawne reguły QTabWidget:
   - QTabWidget { background-color: #191923; }
   - QTabWidget::pane { background-color: #191923; border: 1px solid #2A82DA; }
   - Zapobiega białym tłom w obszarach zawartości zakładek

2. Dodano kompleksowe reguły QTabBar:
   - QTabBar { background-color: #191923; }
   - QTabBar::tab { background: #2D2D37; color: #DCDCE6; }
   - QTabBar::tab:selected { background: #2A82DA; color: white; }
   - QTabBar::tab:hover { background: #3D3D47; }
   - Zapewnia że zakładki zawsze utrzymują ciemny motyw

3. Dodano globalne domyślne QTableWidget:
   - Tło: #1a1a1a
   - Tekst: #DCDCE6
   - Tła itemów: #1a1a1a
   - Zaznaczenie: #2A82DA
   - Nagłówki: #2D2D37 z tekstem #DCDCE6
   - Fallback dla tabel bez jawnych stylów

4. Dodano reguły QStackedWidget:
   - Tło: #191923
   - Zapewnia że kontenery widgetów stosu pozostają ciemne

5. Ulepszone reguły QHeaderView:
   - Spójne kolory nagłówków we wszystkich tabelach
   - Zapobiega białym nagłówkom

Szczegóły techniczne:
Bug występował ponieważ:
- Dziedziczenie Qt stylesheet może się łamać podczas dynamicznego tworzenia widgetów
- Przełączanie zakładek może odtwarzać widgety lub resetować ich konteksty stylu
- Widgety bez jawnych stylów wracają do QPalette/domyślnych systemowych
- Paleta systemowa może nadpisać paletę aplikacji w pewnych sytuacjach

Naprawa zapewnia:
- Każdy typ widgetu ma jawne reguły ciemnego motywu
- TabWidget i jego dzieci utrzymują style podczas przełączania
- Tabele zawsze otrzymują ciemne tła jako fallback
- Stacked widgets (używane dla zawartości zakładek) pozostają ciemne
- Brak możliwości przecieku domyślnych systemowych

Rozwiązanie: Bezpieczny dostęp do session_id z try-except w callbacku
Pliki: app/ml/training/recorder.py:205-211

ROZWIĄZANIE - REDUKCJA SZUMÓW:
RecordingController._apply_noise_reduction() z scipy.signal:
- Filtr Butterworth górnoprzepustowy (80Hz cutoff) usuwa dudnienie/szum
- Noise gate (0.01 RMS threshold) tłumi hałas tła o 50%
- Soft clipping (-0.95 do 0.95) zapobiega zniekształceniom
- Domyślnie włączone (noise_reduction_enabled=True)

ROZWIĄZANIE - FUNKCJA PAUSE:
- Dodano stan PAUSED do RecordingStateEnum FSM
  FSM: IDLE → STARTING → RECORDING → PAUSED → RECORDING → STOPPING → IDLE
- LabeledRecorder.pause_recording() i resume_recording()
- RecordingController udostępnia pause/resume do UI
- Przycisk Pause w ML Training:
  * ⏸ Pause (żółty) → ▶ Resume (zielony)
  * Bloki audio pomijane podczas PAUSED
  * Wskaźnik FSM pokazuje PAUSED w kolorze żółtym

ROZWIĄZANIE - CZYTELNOŚĆ UI:

## 4. WCZEŚNIEJSZE NAPRAWY (k0019-k0022)
================================================================================

✓ k0019 - Naprawa DEADLOCK w ML Training
-----------------------------------------
Problem: Przycisk Start w ML Training zawieszał cały program
Przyczyna: threading.Lock() nie jest reentrant - ten sam wątek próbował
           dwukrotnie zablokować mutex
Rozwiązanie: Zmiana na threading.RLock() (reentrant lock)
Pliki: app/ml/training/recorder.py:90

✓ k0020 - Crash Self-Testu FSM NoneType
----------------------------------------
Problem: Self-test padał z błędem 'NoneType' object has no attribute 'session_id'
Przyczyna: Synchroniczny callback wykonał się zanim przypisanie się zakończyło
Rozwiązanie: Bezpieczny dostęp do session_id z try-except w callbacku
Pliki: app/ml/training/recorder.py:205-211

✓ k0021 - Niewidoczny Tekst w UI (Niski Kontrast)
--------------------------------------------------
Problem: Tekst niewidoczny w zakładkach Detection Audio, ML Training, Analysis
         (jasny szary na białym tle)
Przyczyna: Brak reguł stylu dla QScrollArea, QTabWidget, QFrame, QGroupBox -
           widgety używały domyślnego białego tła systemowego
Rozwiązanie: Dodano jawne ciemne tło dla wszystkich widgetów kontenerowych
Pliki: app/main.py:238-293 (stylesheet)

✓ k0022 - Weryfikacja Radaru w Self-Teście
-------------------------------------------
Problem: Self-test nie weryfikował czy radar działa (skarga użytkownika:
         "Test ma pokazywać ze działa!")
Rozwiązanie: Dodano 4. test "Radar rendering" - testuje TargetTracker + widget radaru
Pliki: app/diagnostics/selftest.py:50,84-136
